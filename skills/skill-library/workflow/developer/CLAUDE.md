# Developer Workflow

> 출처: [obra/superpowers](https://github.com/obra/superpowers) + context7 MCP
> 이 워크플로우를 프로젝트의 `.claude/` 디렉토리에 복사하면 개발자 중심의 AI 코딩 환경이 구성됩니다.

## 핵심 원칙

- **테스트 먼저 작성** (TDD): 실패하는 테스트 없이 프로덕션 코드를 작성하지 않는다
- **체계적 접근**: 추측이 아닌 프로세스를 따른다
- **복잡도 최소화**: 단순함을 목표로 한다
- **주장보다 증거**: 완료를 선언하기 전에 반드시 검증한다

## TDD (테스트 주도 개발) 규칙

```
실패하는 테스트 없이 프로덕션 코드를 작성하지 않는다
```

1. **RED** - 실패하는 테스트 하나를 작성한다
2. **RED 확인** - 테스트가 올바르게 실패하는지 반드시 확인한다
3. **GREEN** - 테스트를 통과시키는 최소한의 코드를 작성한다
4. **GREEN 확인** - 모든 테스트가 통과하는지 확인한다
5. **REFACTOR** - 코드를 정리한다 (테스트는 계속 통과해야 한다)
6. **반복** - 다음 테스트로 이동

예외: 프로토타입, 생성된 코드, 설정 파일 (팀과 협의 필요)

## 체계적 디버깅 프로세스

1. **증상 수집** - 에러 메시지, 로그, 재현 단계
2. **가설 수립** - 가능한 원인 목록 작성
3. **가설 검증** - 하나씩 체계적으로 검증
4. **근본 원인 수정** - 증상이 아닌 원인을 고친다

## 브레인스토밍 규칙

- 모든 프로젝트는 설계를 거친다 (아무리 단순해 보여도)
- 프로젝트 컨텍스트를 먼저 파악한다
- 한 번에 하나의 질문으로 요구사항을 명확히 한다
- 2-3개 접근법을 제안하고 트레이드오프를 설명한다
- 설계 문서를 작성하고 사용자 승인을 받는다
- 승인 후에만 구현 계획으로 넘어간다

## 코드 리뷰 체크리스트

- 계획 준수 확인
- 아키텍처 및 SOLID 원칙
- 에러 처리 및 보안
- 테스트 커버리지
- 코드 품질 및 가독성

## 작업 규칙

1. **컨텍스트 수집** - 기존 기능을 이해하고 가정하지 않는다
2. **계획 수립** - 외부 라이브러리는 context7 MCP로 정확한 문법을 확인한다
3. **분할 정복** - 높은 응집도, 낮은 결합도. 작은 파일 단위
4. **TDD 엄수** - 테스트 작성 → 실패 확인 → 최소 구현 → 통과 확인 → 통합
5. **검증** - 코딩 후 lint + build로 문법 오류 수정
6. **문서화** - 주석과 문서는 한국어, 간결하게
7. **보안** - 하드코딩된 비밀값 없음, CSRF/SQLi 방어, 사용자 입력 검증
8. **근본 원인만** - 임시 방편이나 빠른 해결책 사용 금지
