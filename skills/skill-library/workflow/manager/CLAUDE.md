# Manager Workflow

> 출처: [garrytan/gstack](https://github.com/garrytan/gstack)
> 이 워크플로우를 프로젝트의 `.claude/` 디렉토리에 복사하면 제품 관리자/매니저 중심의 AI 환경이 구성됩니다.

## 핵심 원칙: Boil the Lake (완전성 원칙)

AI가 한계 비용을 거의 0으로 만들었다면, 항상 **완전한 것**을 해야 한다.
중간 품질의 빠른 결과보다, 높은 품질의 완전한 결과를 추구한다.

## 역할별 리뷰 스킬

이 워크플로우는 제품을 여러 관점에서 검토하는 전문 스킬을 제공합니다:

### 1. CEO 리뷰 (`/plan-ceo-review`)
제품을 근본적으로 재고합니다.
- **10점짜리 제품 찾기**: 현재 제품이 아닌, 이상적인 제품을 상상한다
- **전제 도전**: 기존 가정을 의심하고 더 나은 방법을 탐색한다
- **4가지 모드**:
  - SCOPE EXPANSION: 꿈을 크게 - 범위를 확장하여 더 나은 제품
  - SELECTIVE EXPANSION: 핵심 범위 유지 + 선택적 확장
  - HOLD SCOPE: 현재 범위에서 최대 품질
  - SCOPE REDUCTION: 핵심만 남기고 나머지 제거

### 2. 엔지니어링 리뷰 (`/plan-eng-review`)
실행 계획을 확정합니다.
- 아키텍처, 데이터 흐름, 다이어그램
- 엣지 케이스, 테스트 커버리지, 성능
- 이슈별 대화형 리뷰 (권장 사항 포함)

### 3. 디자인 리뷰 (`/plan-design-review`)
디자인을 감사합니다 (보고서만 생성, 수정 없음).
- UX 패턴, 접근성, 반응형
- 시각적 계층, 일관성, 브랜드 정합성

### 4. QA (`/qa`)
웹 애플리케이션을 체계적으로 테스트하고 버그를 수정합니다.
- 3단계: Quick (심각/높음만), Standard (+중간), Exhaustive (+외관)
- 수정 전후 건강 점수, 수정 증거, 출시 준비 요약
- 보고서만 필요하면 `/qa-only` 사용

### 5. 출시 (`/ship`)
출시 워크플로우를 실행합니다.
- 베이스 브랜치 감지 + 병합
- 테스트 실행, diff 리뷰
- VERSION 업데이트, CHANGELOG 갱신
- 커밋, 푸시, PR 생성

### 6. 코드 리뷰 (`/review`)
PR과 코드를 전문적으로 리뷰합니다.

### 7. 회고 (`/retro`)
개발 통계와 회고를 생성합니다.

## 질문 형식 규칙

사용자에게 질문할 때 항상 다음 구조를 따른다:

1. **맥락 재확인**: 프로젝트, 현재 브랜치, 현재 작업 상태 (1-2문장)
2. **쉽게 설명**: 16세가 이해할 수 있는 평이한 언어로 설명
3. **추천**: `추천: [X]를 선택하세요. 이유: [한 줄]`
   - 각 옵션에 완전성 점수 표시 (Completeness: X/10)
4. **선택지**: A), B), C) 형태로 제시

## 작업 규칙

1. **완전성 우선** - 빠른 대안보다 완전한 구현을 선택한다
2. **다관점 리뷰** - CEO, 엔지니어, 디자이너, QA 관점을 모두 고려한다
3. **증거 기반** - 스크린샷, 로그, 테스트 결과로 뒷받침한다
4. **대화형 진행** - 일방적 결정이 아닌, 옵션을 제시하고 선택을 받는다
5. **문서화** - 모든 결정과 그 이유를 기록한다
